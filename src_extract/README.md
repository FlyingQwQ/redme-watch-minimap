# REDMI Watch 6 原生街道地图

这是独立的 Xiaomi Vela JS / Quick App 工程。地图在原生 `.ux` 页面中用 `<stack>` 和 `<image>` 逐张显示 XYZ 栅格瓦片；没有浏览器 DOM、Canvas、WebGL、WebView 或第三方地图渲染引擎。

## 当前功能

- Web Mercator 坐标投影、地理坐标与屏幕坐标互转、经线环绕、瓦片父子关系和动态视口瓦片规划。
- 单指拖动以 80ms 合并更新，仅修改可见图片位置；拖动期间不新增或删除任何原生图片节点，触摸事件使用闭包保存最新坐标，松手后提交中心、合并待处理瓦片、规划瓦片并恢复下载。
- 极低性能配置关闭捏合预览和双层缩放过渡；只通过屏幕上的 `+ / −` 按钮缩放，拖动时暂停新下载，松手后恢复补图。
- 瓦片、定位点和控件分属独立的全屏 `<stack>` 图层，瓦片异步到达时控件仍保持在最上层。
- 本地缓存写入或图片解码失败时，退回 `@system.fetch` 的临时图片 URI，避免缓存能力异常导致整张地图空白。
- 不再在最上层放置全屏透明 `<scroll>`。旧版侧轮适配层会在手指滑动时与地图触摸处理争抢手势，并在滚动回调中调用 `scrollTo` 复位；风险高于收益，已移除。缩放改用屏幕按钮。
- 定位蓝点、跟随/自由浏览模式和重新居中按钮。用户拖动后停止自动居中，GPS 继续更新蓝点。
- 使用 `@system.fetch` 获取图片字节及 HTTP 状态/缓存头，使用 `@system.file` 写入私有缓存。网络请求最多并发 1 个；视口中心优先、重复请求合并，失效瓦片使用 ETag / Last-Modified 再验证。单张图片组件报错时不再自动强制重下整个视口；点按状态卡才会重试，避免失败时产生请求倍增。
- 设备宽度和 DPR 用来把 256px 源瓦片换算成页面坐标，瓦片四边按屏幕像素网格对齐，减少相邻瓦片因小数位置产生的亮缝/暗缝。热修版本关闭屏幕外预加载。
- 低内存配置下，当前地图最多保留 12 个瓦片节点，关闭缩放过渡图层；缓存命中时每 90ms 最多新增 4 个图片节点，避免一次性解码整屏瓦片造成内存尖峰。内存瓦片记录目标上限为 6 张（当前视口所需记录优先保护，可能达到 12 张），持久缓存最多 16 张且以 2 MiB 为目标上限。服务端缓存期限优先，响应未给出期限时使用 7 天。过期缓存仍可先显示，网络请求失败时继续保留旧图。
- 文件持久化不可用时，尝试使用 Vela `fetch` 返回的临时图片 URI；此模式仅在当前运行期间保留瓦片。
- 网络状态、HTTP 403/429/5xx、无效图片、定位失败和图片解码失败都有反馈。顶部状态卡片可点按重试当前视口。
- 地图底部常驻显示 `© OpenStreetMap contributors`。

## 工程结构

```text
src/
  common/map/
    config.js              地图源、缩放范围、缓存和请求上限
    projection.js          EPSG:3857 / XYZ 纯计算
    engine.js              中心点、缩放、视口、锚点与屏幕换算
    gesture-controller.js  触点、拖动和捏合几何计算
    tile-manager.js        请求队列、去重、缓存、过期与失败处理
    tile-layout.js         DPR 换算、像素网格对齐、平移期间旧瓦片保留
    location-manager.js    Vela 定位校验、漂移/跳点过滤
  pages/index/index.ux     原生地图图层和小屏控件
  manifest.json            Watch 应用声明及定位权限
tests/map-core.test.js     Node 内置断言测试，无额外测试依赖
```

地图容器尺寸从 `onShow` 后调用 Vela `getBoundingClientRect` 测量；源瓦片像素按设备宽度、DPR 和实际视口坐标换算。热修版本不再对整层图片绑定高频 `transform`，而是限速更新可见瓦片的位置，降低图层合成负载。Watch 6 真机上的触摸流畅度与长期稳定性仍待实测。

需要 Node.js 和 npm。首次在独立副本中安装依赖：

```sh
npm ci
npm test
npm run build
```

开发包输出到：

```text
dist/com.example.redmiwatch6.map.debug.0.1.13.rpk
```

使用 Xiaomi AIoT / Vela IDE 或已配置的 Vela 设备/模拟器部署此 `.rpk`。开发服务器命令是 `npm start`。此工作区没有配置 Vela 模拟器镜像，也没有 `adb`，所以这里不能启动模拟器或安装到 REDMI Watch 6。

## 地图源与使用规则

图源目录位于 `src/common/map/providers.js`，地图参数位于 `src/common/map/config.js`；运行时使用设置中记住的来源。默认法国社区源配置如下：

```js
TILE_SOURCE_ID: 'osmfr-v1',
TILE_URL: 'https://a.tile.openstreetmap.fr/osmfr/{z}/{x}/{y}.png',
TILE_ATTRIBUTION: '© OpenStreetMap / ODbL · Tiles: OSM France',
USER_AGENT: 'RedmiWatch6NativeMap/0.1.13 (Xiaomi Vela)'
```

默认图源为 OSM 法国社区 PNG 街道底图，无需 Key。官方使用规则：https://www.openstreetmap.fr/usage/ ：免费非营利移动应用须提供清晰署名、标识应用的 User-Agent，控制适度流量并满足公开使用等条件。样式源代码：https://github.com/cquest/osmfr-cartocss 。本应用只请求当前视口，保持单并发，不预取，不批量下载。该图源是海外社区服务，不承诺大陆网络或手表链路速度，部分地名采用法语本地化。

`osmfr-v1` 与旧 `osm-standard-v1` 使用不同的缓存键，因此不会把旧图源的瓦片误用于新样式。磁盘缓存共享容量上限，旧文件随缓存淘汰逐步移除。
面向大陆稳定使用，建议使用有明确客户端调用授权和署名要求的国内瓦片服务。天地图是可研究的官方选项，但需申请开发许可密钥；完整矢量底图还需叠加注记层。本工程没有密钥，也未在大陆网络/Watch 6 真机验证，不能把它描述为已接通。拿到提供者许可和密钥后，在 `config.js` 中配置 URL、图层/认证方式和对应 `TILE_ATTRIBUTION`；若需要分离底图与注记，需把两层纳入瓦片缓存和原生图片渲染。不要硬编码不属于自己的密钥或抓取高德/百度等未授权瓦片。

应用只对当前视口发起交互瓦片请求，不预取区域、不批量下载、不制作离线包。正式发布时，请配置明确允许手表客户端访问、缓存和分发方式的瓦片提供者，并同步修改 `TILE_SOURCE_ID`、稳定的应用标识和页面署名。

网络瓦片请求会向地图提供者暴露用户正在查看的大致地图区域。GPS 坐标只用于本地更新地图中心/蓝点，没有上传 GPS 点的代码。Vela 文档没有声明定位结果的坐标基准；在中国大陆若设备返回 GCJ-02 而底图使用 WGS 84，蓝点可能出现偏移，须在实机检查后决定是否转换。

## 0.1.4 稳定性修复与设备依据

官方规格确认屏幕 432×514、60Hz、内置 GNSS、512MB 可用存储；未公开 CPU 型号/频率、RAM 或单应用堆额度。512MB 不可当作运行内存。规格来源：https://www.mi.com/global/product/redmi-watch-6/specs/ 。

Vela fetch 文档未提供取消请求方法：https://iot.mi.com/vela/quickapp/zh/features/network/fetch.html 。原超时计时器释放逻辑名额，但底层请求仍可能进行，本版本保留名额直到原生回调完成。名额在模块级跨页面共享，避免退出重进后叠加旧请求。若原生接口永远不返回，后续请求会暂停；没有伪造取消。

拖动限速 150ms、规划限速 600ms，复用图片列表并更新节点位置；禁用实时捏合缩放和双层过渡。下载期间验证 PNG/JPEG 头部尺寸为 256×256 且压缩数据不超过 128KiB；这不是完整图片解码验证，文件 URI 兼容模式无法使用同一字节检查。无真机日志，因此尚未证明整机重启根因，也未测得真机帧率/内存峰值。

失败瓦片历史保留约 48 条，视口切换时清理，避免在网络长期失败时随浏览区域无限增长。

## 0.1.5 首次显示、视口剔除与定位修复

缓存索引异步读取完成后主动启动请求队列，修复首次进入要触摸屏幕才开始补图。瓦片元数据缓存与 visibleTiles 图片节点分开；仅与屏幕相交的瓦片进入原生渲染列表，拖动时剔除完全移出的节点。同一组可见 ID 保持节点稳定，并在缓存元数据刷新后同步位置。部分可见的 256px 瓦片仍需完整解码。

GPS 单次请求最长等待 60 秒，结束后再启动订阅，不同时发起这两种定位调用；手动请求去重，重新定位恢复跟随模式，页面退出和重进使用代次标识忽略过期回调。支持显示 203（官方定义不支持）、204（超时）及其他错误码，不假设错误码就是权限错误。定位按钮可以重新发起请求；没有定位结果时北京仅是默认浏览中心，不能当作 GPS 成功。

新增回归覆盖：异步缓存启动无需触摸、拖动出入视口的节点剔除与恢复、元数据刷新后的节点稳定性、定位请求去重、超时后重试与过期生命周期回调。测试使用模拟 API；未在 Watch 6 上确认真实搜星、网络连通性和原生图片帧率。

## 0.1.6 前台保持亮屏

声明 system.brightness 并使用官方 setKeepScreenOn：onShow 开启，onHide/onDestroy 关闭。接口失败时记录日志，不循环调用，不改屏幕亮度。官方页面：https://iot.mi.com/vela/quickapp/zh/features/system/brightness.html 。文档定义该方法，但未在此页列出 Watch 6 的单项支持矩阵，固件实际效果仍需真机确认。持续亮屏会增加耗电。

## 0.1.7 切换 OSM 法国社区源

按用户选择切换到 `https://a.tile.openstreetmap.fr/osmfr/{z}/{x}/{y}.png`，更新署名、应用标识和源缓存键。不再使用已暂停的 OSMChina 地址。常亮、定位和极低性能策略沿用前一版。新源经过开发网络少量样例探测，未完成大陆和 Watch 6 访问验证。

## 0.1.8 每瓦片加载反馈

使用 Vela 原生 progress type=arc，为可见未完成瓦片显示小圆环：排队静态灰环、请求/图片解码中转动浅蓝圆弧、失败红环。下载API不提供字节进度，因此弧段为不确定进度指示，不展示百分比。image complete 后移除提示；加载错误停止动画。屏幕外不创建提示节点，动画共用300ms定时器，拖动期间暂停角度更新，后台/销毁/无活动加载时清理定时器。

官方依据：https://iot.mi.com/vela/quickapp/zh/components/basic/progress.html ，https://iot.mi.com/vela/quickapp/zh/components/basic/image.html 。真机样式和动画开销仍需确认。

## 0.1.9 长按设置与图源记忆

地图空白区域使用官方 longpress 事件打开原生 /pages/settings 页面。支持当前 OSM 法国社区与此前 OSM 标准源；显示上次使用来源，可一键切回。通过 system.storage 自动保存当前来源、上次来源、隐藏底部提示和加载圆环开关，返回地图时读取应用，重新启动也恢复。保存失败会提示，并保留原设置。

隐藏底部提示后，必要来源署名移到顶部小字，不完全移除署名。圆形加载提示可以独立关闭，关闭后不会运行其动画定时器。设置页无地图图片图层；原地图进入后台暂停请求调度、定位与加载动画。

每个图源拥有独立缓存键。切换复用同一缓存/请求管理器，避免并发写同一缓存索引；已经开始的旧源请求仍使用自身固定URL，迟到结果不作为新源地图显示。

官方 router 文档称无需声明，但当前 AIoT 2.0.5 构建器实际检查要求 system.router，本工程显式声明以通过构建。官方依据：通用 longpress 事件、system.router.push/back、system.storage.get/set。真机长按识别与页面切换仍需验证。

## 0.1.10 只显示当前活动瓦片的加载提示

同时最多一个圆环：优先显示正在请求的可见瓦片，无请求时可显示正在解码的瓦片。排队、失败、成功和屏幕外瓦片不显示提示。图片组件发生 error 时移除该失败URI对应的原生 image 节点，避免系统错误占位图和自定义提示重叠；重绘不重复插入同一失败URI，重试获得新的URI后才重新显示图片。请求错误继续由顶部状态提示反馈。

## 0.1.11 拖动专用更新路径

高频触摸点保存在闭包缓冲内，不在每次 touchmove 修改 Vela 绑定的 gesture 对象。显示更新以 64ms 合并，理论更新上限约16次/秒；这不是实测帧率。拖动仅更新可见图片的 left/top，尺寸不变；可见成员未变化时保留原数组与节点。保持屏幕像素对齐、经线环绕和屏幕外剔除。

拖动期间不规划瓦片、不重建加载圆环、不整理图片完成/失败字典，不启动新下载。松手时提交最后一份输入，即使它晚于最后一帧，再计算视口并补图。已经进行的请求仍无法原生取消，返回图片和图片解码仍可能影响流畅度。

目前是PNG栅格地图，不是矢量渲染器。Vela原生 image 不能直接显示矢量地图PBF；转向矢量通常需要另外实现几何解码、道路和文字排版绘制，不能视作当前设备的直接性能替换。本版没有重引入整层高频transform或双层图片过渡。缺少Watch 6性能采样和崩溃日志，尚无法证明达到真机流畅或完全消除重启风险。

另修复侧轮滚动适配层在手指拖动时反复 scrollTo 复位的冲突；手指滚动事件直接忽略，松手后只复位一次。回归测试模拟1000个滚动事件，确认拖动过程中没有原生复位调用。

## 0.1.12 隐藏底部内容与失败边框

按用户明确要求，隐藏底部提示时通过 if 移除底部组件，不再移到顶部；设置仍持久保存。可见请求失败或解码失败瓦片用2px红色边框标记，没有感叹号和失败文字，不创建失败图片节点。关闭圆形加载提示仍保留红色失败边框。恢复有效图片后移除边框，已有有效缓存的更新请求失败不覆盖该图。拖动时红框复用仅位置更新路径，不额外规划瓦片。

## 0.1.13 香港默认中心与算法减负

未获取实际定位前，默认中心改为香港中环附近（22.2819, 114.1589）；GPS成功后仍可按跟随模式居中实际位置。没有声称默认坐标是定位结果。

拖动布局在可见成员不变时不再创建临时索引表/数组/节点，仅边缘进出时分配结果数组；一般区域避免每瓦片做经线环绕除法，接近世界边界时仍正确处理。空的失败边框列表直接返回。输入按物理像素取整，未跨像素时跳过本帧；读取手势坐标不再创建delta对象。

相同瓦片范围复用规划记录，范围、图源、缩放或瓦片尺寸变化才重建。GPS蓝点投影按经纬度、缩放和瓦片尺寸缓存，拖动期间只换算屏幕位置。维持既有单并发、瓦片节点上限、严格视口剔除、64ms更新预算和松手补图，不增加图片缓存或整层动画。

新增回归覆盖香港默认坐标、规划缓存复用及失效、旧请求记录保护、GPS投影计算次数与缓存失效、重复像素输入跳帧。仍没有Watch 6实测帧率、堆内存或CPU占用；这些优化减少可确认的JS工作量，不能据此声称低端设备已流畅。

按用户提供的32MB整机RAM约束进一步收紧：地图元数据/节点最多保留12张，内存记录缓存目标6张且保护当前视口（可达12张），单并发。9张256×256 RGBA的基础像素缓冲理论值约2.25MiB，尚未计入解码、原生缓存、UI和系统内存，不等于实测总占用。没有用低于整屏需求的硬截断制造缺图。侧轮滚动适配内容高度改为视口高度+512逻辑像素，基准256，避免维护6000像素高的滚动布局。没有假定设备32MB均可供应用使用。

内存预算边界更正：432×514视口在特定偏移下会跨越3列×4行，共12块瓦片。元数据/可见节点上限修正为12，避免硬截9块导致空洞。最坏基础RGBA像素缓冲约3MiB，并非固定持有12张；只渲染实际相交部分，没有新增屏幕外预取。单应用总内存与原生解码缓存仍未知，不能把3MiB描述为总占用。

## 0.1.14 滑动闪退排查与视图模型瘦身

用户真机反馈：地图加载期间滑动屏幕会导致应用退出，设备为 REDMI Watch 6、整机内存约 30MB。此工作区没有该设备的崩溃日志或内存采样，无法证明单一根因；以下修复针对代码中可以确认的高风险路径，必须真机复测才能确认是否消除闪退。

1. **非 UI 数据移出视图模型**。Vela 官方内存优化文档明确说明 `private/protected/data` 会对赋值数据递归建立观测；旧版把 `engine`、`tileManager`、`locationManager`、`gesture`、`tiles`、`imageReady/imageErrors` 全部声明在 `private`，滑动手势和每张瓦片回调都会进入数据代理与模板比对。0.1.14 只保留模板真正绑定的字段，运行时对象改为脚本模块级状态。依据：https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html 。
2. **移除全屏透明 `scroll` 侧轮适配层**。该组件覆盖整个地图，`scroll-top` 又是绑定属性；手指滑动会同时驱动地图触摸处理和原生滚动，滚动回调还会调用 `scrollTo` 复位。滑动闪退最可疑的原生路径已被删除，缩放保留屏幕按钮。
3. **拖动期间冻结图片节点**。瓦片回调现在先暂存，最多每 50ms 合并一次；手指按下期间不合并新瓦片、不新增/删除 `<image>`、不重建加载圆环，松手后一次性提交、补图。避免“加载中 + 滑动”时原生解码、节点插入和手势更新同时发生。
4. **加载提示改为普通视图**。移除 `progress type="arc"` 原生圆弧与 300ms 周期重绘，改用 `div` 圆环加“加载”文字，仍然只给当前活动瓦片显示一个提示，避免加载期间额外的原生组件和定时器。
5. **可见节点只保留渲染字段**（`id/src/left/top/width/height`），不再把 `z/x/y/unwrappedX/size` 等元数据塞进视图模型；失败边框节点同样精简。
6. **拖动刷新上限从 64ms 调整为 80ms**，并继续按物理像素取整、未跨像素时跳过本帧。
7. 页面销毁时释放定时器、瓦片管理器、图片映射，并尝试调用 `global.runGC()`；`global.runGC` 不存在时静默跳过。

这些改动减少的是可确认的观察者、模板重绘和原生节点变更量，不等于已经测得真机内存峰值或帧率。若仍闪退，需要抓取手表侧应用日志（崩溃前后最后 100 行）以及内存占用曲线，再定位是原生图片解码、网络回调还是固件限制。

## 0.1.14 正式包签名

`aiot release` 的 production 模式要求 `sign/release/private.pem` 与 `sign/release/certificate.pem`。本工程使用 OpenSSL 生成了自签名 RSA-2048 证书（有效期 10 年，CN 为包名），放在 `sign/release/`；debug 构建仍然使用 toolkit 内置调试证书，两者互不影响。

- 私钥用于后续版本升级签名，必须妥善保管：丢失后无法再用同一身份更新；泄露后他人可以签出被设备视为同一应用的包。
- 自签名 release 包适合开发/内部安装。若要上架小米应用商店或在未开放调试授权的零售手表上自动安装，仍需走小米 Vela 开发者认证、审核和官方签名流程；本工程无法替用户完成平台侧证书签发。
- 重新生成正式包：`npm run release`，产物为 `dist/com.example.redmiwatch6.map.release.0.1.15.rpk`。

## 0.1.15 加载失败、红框与请求排查

用户反馈 0.1.14 仍会闪退，并询问失败红框是否会一直渲染、画布尺寸是否会叠加、图片请求为什么经常没有结果。

- **没有画布**。地图由固定 432×514 的 `<stack>` 图层和 `<image>` 节点组成，没有 Canvas/WebGL。`viewWidth/viewHeight` 只在测量视口时赋值，不会随拖动或失败次数累加；可见图片节点上限 12，失败边框节点也只来自当前视口。
- **红框会剔除**。失败边框只给当前视口内的计划瓦片生成，并且 0.1.15 起按视口裁剪 `left/top/width/height`；瓦片移出屏幕后由 `PanLayout.update` 剔除，失败列表为空时直接清空，不会在屏幕外持续渲染。
- **图片请求实际检查**。开发环境（非大陆出口）请求 `a.tile.openstreetmap.fr/osmfr/15/26774/14302.png` 返回 HTTP 200、`image/png`、256×256、32,877 字节，能通过本工程的 256×256/128KiB 校验；`tile.openstreetmap.org` 在同一环境出现 TLS 连接失败。两个源都在海外，中国大陆网络是否可达、速度和稳定性没有保证。
- **大陆可用性**。当前没有内置可商用的大陆瓦片源；高德/百度等未授权瓦片不应直接抓取。可靠方案是申请天地图密钥，或自建/使用有授权的瓦片代理。拿到授权地址和密钥后，可在 `config.js` 中替换 `TILE_URL` 与署名；天地图还需要底图与注记两层的授权配置。
- **0.1.15 修复**：
  - 瓦片字节先复制成精确长度的 `Uint8Array` 再写文件，避免 Vela 返回的视图附带更大底层缓冲导致图片文件损坏；JPEG 使用 `.jpg` 扩展名。
  - 可见瓦片文件在渲染期间保持 pin，淘汰文件改为延迟删除，避免原生 `<image>` 还在解码时文件被删。
  - 捕获 fetch 超时后释放逻辑请求名额（最多保留 2 个无法取消的原生请求），一次挂起不再永久堵死所有后续瓦片；文件目录、索引、access、writeArrayBuffer、writeText 都增加超时兜底。
  - `mkdir/readText/list` 任一原生回调挂起时，最多 3 秒后退化为临时图片模式，不会永远停在“地图加载中”。
  - 连续 3 次瓦片失败后进入 10 秒冷却，减少被墙网络下无意义的请求和重绘；手动点按状态卡会立刻重置冷却。
  - 缓存命中时按每批 4 张、90ms 间隔逐步创建图片节点，降低首次加载/缩放时的原生解码内存尖峰。
  - 页面隐藏（进入设置或息屏）时主动清空图片节点和失败边框，返回时从缓存重新发布；长按设置改为松手后打开，避免触摸过程中切换页面。
- 仍没有 Watch 6 真机日志，无法证明闪退已彻底消除。若 0.1.15 仍退出，需要提供崩溃前后日志；在没有日志的情况下继续猜测原生崩溃根因没有可靠依据。

## 0.1.16 右滑返回、失败框与图源

- **右滑不是闪退，是系统返回手势**。Vela 的 `onBackPress` 会在右滑/实体返回键时触发；根页面不拦截就会回到应用列表。0.1.16 在地图页实现 `onBackPress()` 并返回 `true`，右滑只取消当前拖动，不再退出应用。设置页新增“退出应用”，调用 `$app.exit()`，需要离开时从设置退出。
- **失败红框偏移已修复**。0.1.15 把红框裁剪到视口，但 `PanLayout.update` 会按瓦片 `x/y` 重新计算失败节点的位置，却保留裁剪后的宽高，拖动后红框与瓦片错位。0.1.16 恢复完整瓦片轮廓，只对与视口相交的瓦片创建边框；完全移出屏幕的瓦片仍会被剔除，失败列表为空时清空，不会累积。
- **地图源建议**：当前内置的 OSM 法国/OSM 标准都是海外服务，中国大陆网络不保证可达。大陆优先推荐**天地图**（官方、需要申请 Key，底图 vec + 注记 cva 两层）；其次是有明确授权的高德/腾讯瓦片服务。OSM/MapTiler/Mapbox 等需要海外网络或 Key。拿到授权 URL 和 Key 后，把 `config.js` 的 `TILE_URL`、`TILE_ATTRIBUTION` 换成对应值即可；天地图需要额外的注记层，当前单层渲染需要再改一处图层逻辑。

## 0.1.17 瓦片接缝修复

- 地图布局不再把 256px 源瓦片按物理 DPR 换算成小数尺寸。Vela 页面本身以 designWidth 为单位排版，`getBoundingClientRect` 返回的也是设计单位；旧逻辑在部分设备上得到 `pixelScale` 不为 1，相邻瓦片分别取整后会出现 1px 级缝隙。0.1.17 固定 `pixelScale = 1`、`tileSize = 256`，让地图数学和图片显示都在同一设计坐标系。
- 每个瓦片的渲染宽高额外加 1 设计像素，向右下重叠 1px，隐藏 Vela 原生图片节点在亚像素边缘上的发丝缝。重叠对 256px 瓦片只有约 0.4% 拉伸，肉眼不可见；失败边框仍使用原始瓦片尺寸，不参与重叠。
- 拖动路径 `PanLayout` 仍然只更新 `left/top`，不改变宽高；瓦片重叠由模板统一处理。

## 0.1.18 模板尺寸与图片显示修复

0.1.17 在模板里写 `width: {{$item.width + 1}}px`，部分 Vela 模板实现对数值绑定做了字符串拼接，可能得到 `2561px` 这类非法尺寸，导致图片节点不显示。0.1.18 不再在模板中做算术：渲染节点新增 `drawWidth/drawHeight` 数值字段，JS 里直接算好 `width + 1`，模板只做数值绑定。图片请求接口本身已验证正常（OSM 法国 256×256 PNG，HTTP 200，约 25–33KB）。

## 0.1.19 取消瓦片重叠

0.1.18 把每张瓦片额外放大 1px 来盖住接缝，但这会让每张图的边缘内容被拉伸 1px，在瓦片边界产生可见的重复/错位。0.1.19 恢复精确 256px 渲染尺寸，`drawWidth/drawHeight` 与 `width/height` 相同；瓦片层底色改成地图浅色底 `#f2efe9`，即使原生图片边缘存在发光丝缝，也会显示为地图底色而不是黑色网格。接缝的根本修复仍是 `pixelScale = 1` 的设计单位布局。

## 0.1.20 取消瓦片层浅色底

0.1.19 给瓦片层加了浅色底 `#f2efe9`，本意是遮住发丝缝，但海面瓦片尚未到达或加载失败时，这个浅色底会从缺口露出来，看起来像海里突然冒出一块陆地。0.1.20 删除瓦片层底色，缺口恢复为地图根层的深色；瓦片本身仍按精确 256px 渲染。
